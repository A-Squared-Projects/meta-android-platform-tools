# meta-android-platform-tools

`android-tools` from AOSP: adbd for the target, and adb, fastboot,
img2simg, simg2img and mkbootimg as native tools.

The recipe fetches the AOSP projects it needs straight from
android.googlesource.com at one release tag (`AOSP_TAG`, `AOSP_PROJECTS`,
`classes-recipe/aosp-projects.bbclass`), and builds them with a make-based
build in place of Soong (`android-tools/build/`) after applying a patch
stack (`android-tools/aosp-patches/`).

It replaces meta-oe's `android-tools` (higher layer priority) and masks
meta-oe's `android-tools_%.bbappend`. meta-oe's `android-tools-conf` is still
used.

Depends on: openembedded-core, meta-oe.

Maintainer: Alex Kiernan <alex.kiernan@gmail.com>. Issues and pull requests
on GitHub.

## On the device

- adbd drops to the `adb` user (created by the recipe) unless `ro.secure=0`.
- `adb root`, `adb unroot`, `adb tcpip` and `adb usb` work as on Android: adbd
  records the change and exits, and expects init to start it again. The
  systemd unit does (`Restart=always`); with another init system, supervise
  adbd (runit, s6, ...), since nothing else restarts it.
- `adb reboot [target]` and `adb remount` need `adb root`. Reboot is
  `${libexecdir}/adbd/reboot` (sync, then reboot(2), passing the target);
  remount runs `ADBD_REMOUNT_COMMAND`, which the image provides.
- Screenshots (`adb exec-out screencap -p`) need a `screencap` command on the
  image.
- Not supported: wireless pairing (`adb pair`, TLS), mDNS discovery,
  fastdeploy, and Android-only services (logcat, bugreport, package
  installs).

Branches follow OE release series: `main` is for master (blacksail),
`wrynose` for wrynose. They differ only where the oe-core series does (e.g.
wrynose's `LICENSE` uses `&`, which its oe-core requires, rather than SPDX
`AND`); changes land on `main` and are merged into `wrynose`.

## Where things come from

- `android-tools-aosp-srcrevs.inc`: generated by
  `bitbake -c update_aosp_srcrevs android-tools` (pins each project to
  `AOSP_TAG`; the fetch fails if it pins a different tag).
- `android-tools/build/`, `android-tools/aosp-patches/`,
  `android-tools-aosp-patches.inc`: generated from the workbench repository,
  [android-platform-tools-aosp](https://github.com/A-Squared-Projects/android-platform-tools-aosp),
  where releases are imported and the patches rebased:

      <workbench>/scripts/export-oe-patches.sh recipes-devtools/android-tools

  The export refuses to run if `AOSP_PROJECTS` and the workbench's project
  list differ.

## New release

1. In the workbench: import the tag, rebase the patches, update `build/`,
   commit, export.
2. Here: set `AOSP_TAG` (and `PV`), run
   `bitbake -c update_aosp_srcrevs android-tools`, build, commit.

## Options

- `PACKAGECONFIG`: `systemd` (readiness via sd_notify), `fs-config`,
  `selinux` (apply `ADBD_ROOT_SECLABEL` with SELinux)
- `ADBD_ROOT_SECLABEL`: the SELinux context or SMACK label for `adb root`
  sessions (`--root_seclabel`, added to the systemd unit; other init systems
  pass it themselves). SMACK needs no PACKAGECONFIG; it's used when active.
- adbd policy is Android's, from properties: `ro.secure`, `ro.debuggable`,
  `ro.adb.secure` in `ADBD_PROPERTY_FILES` (default
  `${sysconfdir}/build.prop:${runtimedir}/build.prop`, later files win). With none
  set, adbd drops to `ADBD_USER` and requires a key from every host; a
  development image sets `ro.debuggable=1`. A file staged while adbd runs
  takes effect when adbd restarts.
- `ADBD_PROPERTY_DIR`: writable properties (default `${runtimedir}/adbd/properties`)
- `ADBD_USER`: the user adbd drops to (default `adb`)
- `ADBD_AUTH_KEY_PATHS`: trusted host key files, colon-separated
- `ADBD_REMOUNT_COMMAND`: run by `adb remount` (default `remount`)
- `ADB_BUILD_ID`: shown by `adb version` / `fastboot --version`
  (default `${PV}`)
